SQL 注入自动检测与修复工具（Java 代码）极简设计文档
适用场景：批量扫描指定文件夹下的 Java 代码文件，仅修复 SQL 注入漏洞，严格保留代码原有结构 / 功能 / 命名，1:1 复刻文件夹目录树，同级生成修复后文件；支持多进程并发处理、可视化配置线上 / 本地大模型。设计原则：极简、无侵入、保真代码、轻量落地
一、项目概述
1.1 项目目标
开发一款轻量级自动化工具，仅专注处理 Java 代码中的 SQL 注入安全问题，不改动任何其他代码逻辑；自动递归扫描源文件夹，并发处理所有 Java 文件，按原目录结构输出修复后的文件到同级新目录；支持页面配置线上 / 本地大模型，满足批量代码安全修复需求。
1.2 核心强制约束（不可突破）
仅处理 SQL 注入：不修改任何非注入相关代码（注释、逻辑、格式、业务代码均不改动）；
代码百分百保真：保留原类名、方法名、变量名、包名、入参、返回值、代码功能；
结构百分百复刻：新文件目录树与源目录完全一致，仅修改文件内容；
无侵入性：不修改源文件，所有修复文件输出到独立新目录；
无额外操作：不编译代码、不重构代码、不新增 / 删除代码文件。
二、核心功能需求
文件扫描：递归读取指定源文件夹下所有 .java 代码文件；
注入修复：通过大模型自动检测并修复 SQL 注入风险（Statement 拼接→PreparedStatement、MyBatis ${}→#{} 等标准修复）；
目录复刻：在源文件夹同级自动生成新目录，1:1 还原原文件夹结构；
多进程处理：支持多文件并发处理，提升批量文件处理效率；
模型配置：极简 Web 页面配置线上大模型（通义千问 / GPT / 文心一言）和本地大模型（Ollama/Llama）；
日志输出：实时展示处理进度、修复文件数、失败文件、漏洞数。

四、核心模块设计
4.1 文件扫描模块
功能：递归遍历指定源文件夹，筛选所有 .java 后缀文件；
输出：文件列表 + 原文件绝对路径（用于复刻目录结构）；
规则：跳过非 Java 文件、空文件，不修改源文件。
4.2 多进程调度模块
技术：Python 进程池（规避多线程 GIL 限制）；
功能：管理并发进程，分配文件处理任务，控制并发数量；
配置：页面可自定义并发数（默认 = CPU 核心数）；
保障：单个文件处理失败不影响其他文件，失败文件记录日志。
4.3 代码 IO 模块
读取：原样读取源文件完整代码；
写入：根据原文件路径，在新目录创建对应文件夹，写入修复后代码；
目录规则：新目录名 = 源目录名 + _sql_fixed（自动创建，无需手动新建）。
4.4 提示词封装模块
核心：生成强硬约束型提示词，强制大模型仅修复 SQL 注入，不改动其他代码；
输出：将提示词 + 原代码封装后，发送给大模型。
4.5 模型适配模块
统一接口：对外提供 call_model(原代码) 方法，屏蔽线上 / 本地模型差异；
支持类型：
线上模型：通过 API Key 调用云端大模型；
本地模型：调用本地部署的 Ollama/Llama 等模型接口。

七、多进程处理设计
进程池：固定大小进程池（页面可配置，默认 4/8 进程）；
